# 「当天用完（不计库存）」选项 设计说明

> 状态：**待负责人批准**（涉及收货时库存怎么加，依规范需先批准设计）
> 日期：2026-10-19

## 1. 情况

冰块这类东西每天进货、当天用完。

- 现在收货一律会加库存，系统里没有任何地方会扣减，所以「当前库存 10 Bag」「库存估值」只会一直往上加，跟实际不符。
- 系统没有「卖出自动扣库存」，所以只能靠盘点修正。但这类东西天天用完，没有人会去盘点它。

类似的还有每天进货的新鲜面、豆芽等。

## 2. 做法

在「编辑库存 › 基本信息」加一个勾选框「**当天用完（不计库存）**」。新增选填字段：`consumeOnReceive?: boolean`。

勾选后：

| 项目 | 行为 |
|---|---|
| 下采购单 | 照常可以下 |
| 收货 | **库存数量不变**（不会加）；收货记录照常写，记下这次收了多少、花多少钱 |
| 应付账款 | 照常按单据金额生成，**完全不变** |
| 成本 | 「每单位成本」更新成这次收货的单价（最近进价），菜谱算成本时照常可以用 |
| 库存估值 | 数量是 0，估值也是 0（钱已经在应付 / 损益里算成当天的费用） |
| 无货 / 低库存提醒 | 不提醒，跟「停订」一样 |
| 盘点 | 不列入盘点清单 |
| 卡片显示 | 显示「当天用完」小标签，数量那一格写「—」 |

勾选时，表单会把「现有库存」改成 0，**按保存才写入**，表单上会提示这一点。

## 3. 改动位置

- `utils/unitConversion.ts`：
  - 新增 `isConsumeOnReceive()`；
  - `getStockStatus` 和 `needsReplenishment` 跟停订一样排除。
- 两个收货入口（供应商页、采购管理）：这类商品的库存数量变化为 0，每单位成本改用这次的单价。共用同一个函数，并加单元测试。
- 盘点清单 / 指派盘点：跳过这类商品。
- 编辑库存：加勾选框，权限跟品名同一组（编辑基本资料）。

## 4. 不改的东西

- 资料结构：只新增一个选填字段，V1 照常读取。
- 应付账款、损益引擎：完全不变。
- 没勾选的商品：行为完全不变。

## 5. 风险

- **V1 不认得这个选项**：在 V1 收冰块，库存还是会加。跟非洲鱼一样，员工全面改用 V2 之后就不会再有这个问题。
- 勾选前已经累积的库存数量（例如冰块的 10 Bag），会在勾选时由负责人确认归 0。归 0 前的库存估值会从库存总值里消失；这部分金额在当初进货时已经记成应付 / 费用，不会重复，也不会漏算。
- 回滚：取消勾选即可恢复原本的算法，不需要还原任何资料结构。
