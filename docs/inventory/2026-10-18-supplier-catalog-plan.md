- 日期：2026-10-18
- 依据：负责人要求「强化供应商目录，加强内容和数据；一个库存有两个以上供应商，价格不同、包装也不同，但是同一样物品，要怎么弄」。

## 1. 现况（代码审查，file:line 以 develop-v2 `790ecbf` 为准）

### 1.1 已经支持的
- 一个库存商品可以被多个供应商品项连结：每个供应商品项各自有 `linkedStockId`。
- 每个供应商品项有自己的价格与换算：`price` / `pricePerPurchaseUnit`、`toBaseRatio`（1 包装 = 几个基础单位）、`costPerBaseUnit`。
- 采购卡片有 2 个以上供应商时，可以手动「更换」（`ProcurementModule.tsx:1584-1625`），列出各家每单位价与每基础单位成本。

### 1.2 问题
| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| A | **包装存在库存商品上，按单位名称比对**。供应商品项存档时，把价格与换算写进库存的 `purchaseUnits`，用「id 或单位名称」找同一笔（`SupplierModule.tsx:491-493`） | 供应商品项存档 | 两家都叫「CTN」但一箱 12 瓶、一箱 24 瓶，**后存的会盖掉前一家的换算与价格** |
| B | **永远选第一个供应商**：`findSupplierForStock` 回传 `all[0]`（`ProcurementModule.tsx:546-549`），没有「常用 / 最便宜」 | 智能补货、盘点补货、快速加入 | 不是按价格或习惯，而是按供应商资料的排列顺序 |
| C | **按供应商补货会放错供应商**：选了供应商 X 补货，品项却用 `findSupplierForStock` 的第一家（`ProcurementModule.tsx:817-822, 872`） | 智能补货（按供应商） | 品项可能跑到另一家的采购单 |
| D | 采购价格换算用**库存上同名单位**的换算，不是供应商品项自己的 `toBaseRatio`（`resolveProcurementPrice`，`ProcurementModule.tsx:160-300`） | 下单价格 | 与 A 一起出错 |
| E | 同一供应商有两个品项连到同一库存（例如散装与整箱），只取第一个（`ProcurementModule.tsx:540`） | 下单 | 第二个包装无法选 |
| F | **没有比价画面**；库存编辑窗的「绑定供应商」只显示供应商名称（`StockEditModal.tsx:1188-1205`） | 查看 | 不知道哪家便宜、包装多大 |
| G | **收货不更新供应商品项价格**；实际进价只留在采购单明细（`finalUnitPrice`、`costPerBaseUnitAtReceive`）与收货记录 | 价格资料 | 目录价格越来越旧，看不出哪家涨价 |
| H | 供应商品项缺少常用资料：品牌 / 规格、包装说明、最少订购量、交货天数、停售标记、备注 | 内容 | 下单时要靠记忆 |

## 2. 设计

### 2.1 原则：「库存商品」是一样东西；「供应商品项」是某家卖的某种包装
```
库存商品：虎牌啤酒 (Tiger Beer)  基础单位 BTL
 ├─ EK FRESH       · 箱 CTN  1 箱 = 24 BTL · RM 120 / 箱 → RM 5.00 / BTL   ★常用
 ├─ AL FROZEN      · 箱 CTN  1 箱 = 12 BTL · RM  66 / 箱 → RM 5.50 / BTL
 └─ 市场临时采购    · 瓶 BTL  1 瓶 =  1 BTL · RM 6.20     → RM 6.20 / BTL
```
- 收货一律换算成基础单位进库存；平均成本照现在的加权平均。
- 比价一律看「每基础单位价格」，包装大小不同也能比。

### 2.2 资料（全部是可选的新字段；V1 不认得也照常运作）
**供应商品项 `CatalogItem`**
| 字段 | 说明 |
|---|---|
| `packDesc` | 包装说明，例如「24 瓶 × 320ml」 |
| `brand`、`spec` | 品牌、规格 |
| `minOrderQty` | 最少订购量（以这个品项的包装计） |
| `leadTimeDays` | 下单到货天数 |
| `status` | `ACTIVE` / `DISCONTINUED`（停售：不再出现在下单与补货） |
| `note` | 备注 |
| `lastReceivedPrice`、`lastReceivedPricePerBase`、`lastReceivedAt`、`lastReceivedPoId` | 最近一次实际收货的价格（收货时自动写） |
| `priceUpdatedAt` | 目录价格最后修改日期 |

**库存商品 `StockItem`**
| 字段 | 说明 |
|---|---|
| `preferredSupply` | `{ supplierId, catalogItemId }`：常用供应商与包装（只能选一个） |

### 2.3 规则
1. **包装跟着供应商品项走**（修 A、D、E）：
   - 下单与收货用供应商品项自己的 `toBaseRatio`。
   - 供应商品项存档时不再按单位名称去盖库存的 `purchaseUnits`。库存上已有的单位保留不动，供旧画面与 V1 读取。
2. **默认供应商**（修 B）：常用（`preferredSupply`）→ 每基础单位最便宜（停售的不算）→ 第一个。采购卡片照样可以「更换」。
3. **按供应商补货只放那一家**（修 C）。
4. **收货时记最近进价**（修 G）：
   - 写 `lastReceived*`，不自动改目录价格。
   - 实际进价跟目录价差超过 5% 时，收货完成提示「要不要更新目录价格」，一键更新，并写 `priceUpdatedAt`。

### 2.4 画面
1. **库存编辑窗「供应商比价」**（取代只有名称的「绑定供应商」）：
   - 每个供应商品项一行：供应商、品项、包装、每包装价、每基础单位价、最近实际进价与日期、价格更新日期。
   - 最便宜标绿色，可设「常用」。
2. **供应商品项编辑窗**：加入 2.2 的内容字段，并显示「1 箱 = 24 BTL，每 BTL RM 5.00」与同一库存其他供应商的价格。
3. **数据审查中心「供应商比价总表」**（只读，可下载 Excel）：
   - 所有有 2 个以上供应商的库存，列出最便宜、最贵、价差、常用是否是最便宜。
   - 目录价格超过 90 天没更新的列出来。
4. **库存资料审计新增**：
   - 同一库存、同一单位名称、不同换算（A 的情况）
   - 目录价与最近实际进价差超过 10%
   - 常用供应商已停售或已删除
