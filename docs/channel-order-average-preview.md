# 日报渠道订单数与平均每单

本轮为本地交互稿，未接ERP、平台API或真实结算资料。

## 展示与填写

- 保留经营日报的营业额、对比、单数与人均区别；新增店内、Grab、Foodpanda、ShopeeFood渠道销售额、完成单数和平均每单。
- 老板在日报查看；管理首页有“补录已结算日的渠道订单数”入口。仅管理端补录页可填写；可编辑或完全权限可填，可查看只读。经营日报没有编辑按钮和订单输入框，无论当前账号权限多高，日报均只展示结果。
- 目前仅所选月份最后结算日有分渠道样例；其他演示日期显示未提供，不能猜渠道金额。
- 输入仅保存在页面内存，刷新重置，不改变营业额、平台扣款或利润。

## 口径

同一渠道平均每单 = 同营业日、同一批完成订单的销售额 ÷ 完成订单数。

演示销售额使用退款调整后、抽佣前的金额；正式接入需与现有渠道营业额字段核对。取消单不计，退款如何归属及完成单定义须与平台账单保持一致。平台扣款、广告费、到账金额分别展示，不能混作销售客单价。

店内“每单消费”不等于堂食“每人消费”；人数缺失时不以订单数代替。全渠道平均每单 = 全渠道完成订单销售额合计 ÷ 完成订单数合计，不是各渠道均价的简单平均。

空白=未补录，0=确认没有完成单。单数需非负安全整数；销售额大于0却填0单需核对；金额0且订单0显示无完成订单，不除以0。全渠道有任何待补或无效渠道时，不显示整体均价。

## 正式实现建议（尚未实施）

按营业日和渠道记录可选的完成订单数字段，null与0分开；不为历史数据统一补0，不从金额反推单数。订单数只是分析维度，不重复记营业额或额外生成订单。

订单数变更保留操作人、时间与更正原因，已结算日的更正沿用ERP授权与审核规则。字段、公式和金额舍入需要Mock/Emulator测试；真实平台与结算记录对账后才能上线。不得擅自改历史结算金额或财务算法。
