# 三角色交互稿

本地演示，不连接 ERP、Firebase、付款或真实库存。所有金额、人员、规格、任务均为模拟。刷新清空操作。

## 已讨论的设计

- 老板先看已结算营业与月度经营：营业额、COGS、人工、暂估利润和异常。今日未结算不冒充实时营业额。电脑展开组成和趋势。
- 管理先处理工作和员工交办；当前按一位管理设计。
- 员工用自己的账号，首页显示岗位指引与交办任务；例行指引不评分、不逐项审批。
- 模块权限三档：可查看、可编辑、完全权限。确认更新盘点需管理或老板拥有完全权限。这里的切换器仅模拟，不是后台授权。
- 指派可按员工或岗位；盘点不分营业中/收档。箱、包、散装按明确规格换算；管理确认后更新库存。

## 体验顺序

1. 顶部选择管理，点指派任务，按员工或岗位指派。
2. 选择员工，打开任务、开始点算。
3. 饮用水填2箱、3包、5瓶，合计71瓶；面粉填1箱、2包、0.5kg，合计12.5kg。没有的数量填0。
4. 提交。管理的可编辑权限只能查看，不能确认更新。
5. 切完全权限，可退回补充或确认并更新演示库存。
6. 确认后保留前后数量、点算人、确认角色与时间，不能重复确认。

## 已验证

- node --check roles.js 通过。
- 浏览器实际走通按岗位指派、开始、空值拦截、71瓶与12.5kg换算、提交不更新库存、可编辑无法确认、退回原因及重新提交、完全权限确认、重复确认禁用、可查看不能指派。
- 手机布局已观察无横向溢出；固定1366像素电脑预览单独提供。

## 范围

仅首页、经营组成和盘点闭环可实际操作。其他业务入口会明确提示尚未接入。此次没有修改现有ERP应用、登录、服务端权限、财务公式、Firestore或CC分支；未合并或部署dev站。

正式实现的期间库存变动核对、后台权限、幂等、事务、审计由后续ERP实现与测试保证；本稿不声称具备生产安全能力。
