# iOS 性能 · 第二阶段：Firestore 读取盘点与并行化（Issue #8）

- 日期：2026-10-13
- 分支：`claude/v2-ios-perf-2` → `develop-v2`
- 原则：**不改变业务逻辑**。读取哪些资料、怎么计算、出错时显示什么都不变，只改变「什么时候发出读取」。

## 1. 盘点结果

工具：`scripts/perf/count-firestore-reads.cjs`。它统计 Firestore Listen 通道的读取目标，只连 Emulator。

| 情境 | 读取数 | 内容 |
| --- | --- | --- |
| 打开网址 → 登录画面 | 2 | `config/store`、`employees`（整集合） |
| 老板输入 PIN → 首页「经营重点」 | 13 | 见下表 |
| 老板首页 → 「全部功能」 | 3 | `roster/main`、`roster/notes`、`logs`（30 笔） |
| 员工登录 → 员工首页 | 8 | 本人资料、通知、角色设定、本人当日考勤、本人待办盘点、`roster/main`、`roster/notes`、班次设定 |

老板首页的 13 项读取：

| 读取 | 有无上限 | 备注 |
| --- | --- | --- |
| `employees/001`（本人） | 单份 | 登录后同步权限 |
| `notifications` | where + limit | |
| `settlements` 最近 30 天 | limit 30 | |
| `settlements` 上个月 | where + limit 31 | |
| `purchase_orders` 待收货 | 服务端计数 | 第一阶段已改为计数 |
| `stock_kitchen` / `stock_bar` / `stock_general` / `stock_fuel` | 整集合 | 已有 5 分钟快取（sessionStorage） |
| `roster/main`、`roster/notes` | 单份 | 旧版整份排班文件 |
| `recurring_bills` | 整集合 | 已有 10 分钟快取，资料量小 |
| `logs` 最近 30 笔 | limit 30 | |
| `standalone_expenses` 未付 / 部分付款 | where，无 limit | 只取未结清的应付 |

**结论：**
- 没有发现重复监听；同一画面内也没有重复读取同一份资料。`onSnapshot` 共 8 处（排队叫号 2、员工待办 1、通知 1、设备帐号 2、Kitchen Alert 2——后者在 PR #15 移除），都已按条件或文件 ID 限定范围。
- **真正的问题是「一个等一个」**：
  - 老板首页的读取依序执行，约 9 轮来回；
  - 员工首页的考勤、排班、班次设定共 4 轮；
  - 登录画面先读门店设定，再读员工名单。
- 手机网络每轮来回约 100–300 ms，在 iPhone 上会累积成明显的等待。

## 2. 改动

| 档案 | 改动 |
| --- | --- |
| `components/BossPriorityDashboard.tsx` | 首页的各项读取在开头同时发出；取用结果的顺序与 `try/catch` 不变（某项失败时，后面的结果照旧不采用，与原本相同） |
| `components/StaffDashboard.tsx` | 本人考勤、排班、班次设定同时发出；取用方式同上 |
| `components/Login.tsx` | 门店设定（Logo）与员工名单同时读取；任一失败仍显示原本的「读取失败」 |
| `utils/dataManager.ts` | `getRosterData` 的 `roster/main` 与 `roster/notes` 两份文件同时读取（共用，所有呼叫者受益） |
| `components/lazyModules.tsx`、`App.tsx` | 停在登录画面 2.5 秒后，在背景先下载登录后的首页程序档（老板入口 → 老板首页，其余 → 员工首页）。只下载程序档，不读写资料；失败就略过，打开时仍走原本的载入与重试流程 |

读取的集合、条件、次数完全不变。改动前后都用工具实测：老板首页 13 项、员工首页 8 项。

## 3. 量测结果

**条件**：
- Chromium 模拟 iPhone 13 画面；CPU 降速 4 倍；下行 9 Mbps、上行 3 Mbps；
- 连接本机 Emulator；登录画面停 5 秒模拟输入 PIN；
- 每个版本量 3 次取中位数。
- 脚本：`scripts/perf/measure-boss-home.cjs`。

| 指标 | RTT 40 ms：改动前 | RTT 40 ms：改动后 | RTT 150 ms：改动前 | RTT 150 ms：改动后 |
| --- | --- | --- | --- | --- |
| 打开网址 → 登录画面 | 2.68 s | 2.57 s | 3.15 s | 3.13 s |
| 按下 PIN → 老板首页画面 | 1.60 s | 1.50 s | 1.68 s | 1.47 s |
| 按下 PIN → 首页资料全部载入 | 2.72 s | **2.12 s** | 3.45 s | **2.05 s（−41%）** |
| 页面错误 | 0 | 0 | 0 | 0 |

网络越慢（RTT 越大），改善越明显，这正是 iPhone 在店内 4G 或 Wi-Fi 不稳时的情况。

> 这是模拟条件下的相对比较，不等于实机秒数。正式 Firestore 的来回时间比本机 Emulator 长，实际改善预计更明显。请在预览站用出问题的 iPhone / iPad 实测。
