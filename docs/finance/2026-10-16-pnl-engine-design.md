## 1. 各模块的角色

| 模块 | 角色 | 进不进经营盈亏 |
|---|---|---|
| 日结钱箱支出（dayExpenses） | 只用于钱箱现金核对。员工录入方式不变，仍影响当日应余现金 | **不进** |
| 应付账款 / 独立支出 | 采购、食材、杂项、维修、包装、软件等费用的正式来源 | 进（按账单日期、全额） |
| 固定账单付款（bill_payments） | 租金、水电等固定费用 | 进（按付款日期，扣除他人分摊） |
| Payroll（薪资单） | 正职薪资的正式来源 | 进（应发 − 无薪假 − 已扣罚款 + 雇主 EPF / SOCSO / EIS） |
| 兼职（parttime_） | 兼职工资，计一次 | 进 |
| 员工预支（STAFF_ADVANCE） | 现金付款与薪资抵扣 | **不进**（已含在应发里） |

## 2. 计算规则（`utils/pnl/engine/pnlEngine.ts`）

经营净利 = 营业额 − 外送平台扣款 − 食材 − 人工 − 其他经营费用。

**营业额**
- 店内 POS 实收，扣退款。
- 外送平台按总额计。旧日结只有 Grab 净额、没有总额时，以净额计，并标「待核对」。

**外送平台扣款**
- 已对账：总额 − 实收。
- 未对账：总额 −（净额 − 广告），标「暂估」。

**收款手续费**：对账自动产生的 `recon_fee_` BANK_FEE 计入。

**应付账款 / 独立支出**
- 按账单日期计入，一律用马来西亚日期。
- 金额 = 全额 − credit note；有拆分时按比例拆。
- 分期付款的 `pay_` 列不重复计。
- 以下几类不计入：
  - 发薪付款纪录（`payroll_`、`salary_`）
  - 固定账单的镜像（`bill_sync_`）
  - 资本支出：保留在传统账目的 CAPEX 段，不进净利
  - 押金、借款、转账、分红

**薪资类独立支出**（SALARY、ALLOWANCE、COMMISSION、EPF / SOCSO 等，兼职除外）
- 以 Payroll 为准，不另计。
- 若有这类记录，月份标「待核对」，请确认是否为薪资单以外另付的钱。

**人工**
- 已发薪：逐人先核对字段，确认无薪假、罚款是否真的从实发扣掉。
  - 对不上的人以应发计，并标「待核对」。
- 未发薪：按员工档案底薪与法定供款暂估。
- 期间不是整月时按天数分摊。
- **不使用 57,300 或任何比例后备值。**

**食材**：以采购金额计，一律注明「采购暂估，非实际耗用」。

**分类**
- 每个分类都落在传统账目的某一行：
  - 宿舍水电 → 员工水电行
  - SUBSCRIPTION → IT 行
  - OTHER → 其他营运费用行
  - JUICE → 饮料行
- 仍不认识的分类，归入同性质的「其他」行，并列出来。

## 3. 状态（只有两种）

**已确认**：以下全部成立。
- 期间已结束、日结齐全、平台全部对账。
- 当月薪资已发放，且字段核对一致。
- 固定账单都有费用。
- 没有疑似重复、没有薪资单以外的薪资类支出。
- 钱箱每一笔都有对应记录。

**暂估／待核对**：其他所有情况，并逐条列出原因。
- 钱箱有支出、但找不到应付账款 / 薪资 / 预支记录时，显示「**费用可能遗漏**」。

## 4. 钱箱核对（`utils/pnl/engine/cashBox.ts`，只读）

每一笔钱箱支出，与应付账款、固定账单付款、兼职、预支记录对照，状态如下：

| 状态 | 条件 |
|---|---|
| 已核对（系统比对一致） | 金额相同 + 名称相符 + 对方是现金付款（兼职、预支本来就是现金） |
| 不一致 | 名称相符、日期相近，金额不同 |
| 待核对 | **只有**金额相同、日期相近：不会自动当成同一笔 |
| 缺少 AP / 费用记录 | 找不到任何可能对应的记录 |

日期容许范围：
- 有付款日期的记录看付款日，前后 3 天。
- 只有账单日期的，账单可以早于钱箱付款最多 31 天。

每笔正式记录只配对一次。「人工确认同一笔」需要写入资料，另案申请批准。
