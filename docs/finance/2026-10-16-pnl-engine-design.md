# 唯一经营盈亏引擎 · 设计说明

- 日期：2026-10-16（同日按负责人核对结果修订）
- 依据：负责人 2026-10-15、10-16 的决定（财务架构调整、杂项费用审计、薪资口径）
- 分两步：
  - **PR A（只读）**：新增引擎，在「盈亏对账」并列显示；驾驶舱旧算法不再计入钱箱支出。传统账目与 Excel 的计算不变。
  - **PR B（切换）**：驾驶舱与传统账目（含 Excel）改读引擎。负责人在盈亏对账核对 9 月数字后才合并。

## 1. 各模块的角色

| 模块 | 角色 | 进不进经营盈亏 |
|---|---|---|
| 日结钱箱支出（dayExpenses） | 只用于钱箱现金核对 | **完全不纳入**：不计费、不与 AP 配对、不做漏账判断 |
| 应付账款 / 独立支出 | 采购、食材、杂项、维修、包装、软件等费用的正式来源 | 进（按单据日期、全额 − CN） |
| 固定账单付款（bill_payments） | 租金、水电等固定费用 | 进（按付款日期，扣除他人分摊；分类与 AP 镜像相同） |
| Payroll（薪资单） | 正职薪资的正式来源 | 进（见第 2 节「人工」） |
| 兼职（parttime_） | 兼职工资 | 进，计一次 |
| 手动登记的工资 / 津贴（SALARY 等） | 例如补发上月少算的工资 | 进，并列出供核对是否与薪资单重复 |
| 员工预支（STAFF_ADVANCE） | 提早发薪，月底从实发扣回 | **不另计**（已含在应发里） |
| 员工借款（STAFF_LOAN） | 资产，不是费用；之后从薪水扣回 | 不进；扣回也不减少人工 |

## 2. 计算规则（`utils/pnl/engine/pnlEngine.ts`）

经营净利 = 营业额 − 外送平台扣款 − 食材 − 人工 − 其他经营费用。

**营业额**
- 店内 POS 实收，扣退款。
- 外送平台按总额计。旧日结只有 Grab 净额、没有总额时，以净额计，并标「待核对」。

**外送平台扣款**
- 已对账：总额 − 实收。
- 未对账：总额 −（净额 − 广告），标「暂估」。
- 平台通道的 `recon_fee_`（MARKETING_FEE）已反映在「总额 − 实收」，不重复计。

**收款手续费**：对账自动产生的 `recon_fee_` BANK_FEE（TNG / 卡 / DuitNow）计入。

**应付账款 / 独立支出**
- 按单据日期计入，一律用马来西亚日期。
- 金额 = 全额 − credit note；有拆分时按比例拆。
- 分期付款的 `pay_` 列不重复计。
- 不计入：发薪付款纪录（`payroll_`、`salary_`）、固定账单镜像（`bill_sync_`）、资本支出（保留在 CAPEX 段，不进净利）、押金 / 借款 / 转账 / 分红。

**人工**（与传统账目一致，负责人 2026-10-16 核对）
- 已发薪：应发 − 无薪假 − 已扣罚款 − 其他扣款 + 雇主 EPF / SOCSO / EIS。
  - 借款扣回、宿舍费**不**减少人工（借款发出时是资产；宿舍费只写在薪资单、实际没扣）。
  - 罚款逐人核对是否真的从实发扣掉；对不上的人以应发计，并标「待核对」。
  - 法定供款按应计计入；未标记已缴时注明。
- 未发薪：按员工档案底薪与法定供款暂估。
- 期间不是整月时按天数分摊。
- **不使用 57,300 或任何比例后备值。**

**食材**：以采购金额计，一律注明「采购暂估，非实际耗用」。

**分类**：每个分类都落在传统账目的某一行；不在对照表的分类按性质并入 INGREDIENTS（其他）/ OTHER OPERATING EXPENSES，并列出来（与传统账目相同）。

## 3. 状态（只有两种）

**已确认**：期间已结束、日结齐全、平台全部对账、当月薪资已发放且字段核对一致、固定账单都有费用、没有疑似重复。

**暂估／待核对**：其他所有情况，并逐条列出原因。钱箱支出不影响状态。

## 4. 与传统账目（2026-10-16 修正后）的差别

两边同一口径的部分：日期、分期付款、固定账单分类、未对应分类、人工。仍不同的地方（PR B 合并后传统账目也改用引擎）：
- 外送平台：引擎在未对账日扣除广告；传统账目没有。
- 收款手续费（BANK_FEE）：引擎计入；传统账目略过。
- 预支的月份：引擎随薪资单月份；传统账目在发放月份。同月发放同月扣回时没有差别。
- 法定供款未缴：引擎按应计计入；传统账目不计。
