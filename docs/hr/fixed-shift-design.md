# 固定员工的上下班时间 —— 设计说明

> 状态：**待负责人批准**（会影响迟到、早退的判断和薪资的迟到扣款，依规范需先批准）
> 日期：2026-10-23

## 1. 现况
迟到、早退现在一律按「考勤设定」判断：
- 平日 / 周末各有一组时间；
- Group A、Group B 各有一组时间（员工档案的「排班分组」）；
- 特别期间可以另设时间。

同一套时间用在三个地方：
- 考勤审核（FACE3000 导入）；
- 考勤主控台；
- 薪资结算的迟到扣款。

有些固定员工（例如后勤、会计）上下班时间跟店面不一样，按 Group A 的时间会被误判迟到或早退。

## 2. 做法
员工档案「资料 → 工作」新增一个**选填**设定：「固定上下班时间」。
- 例如 09:00–18:00。可以选每星期哪几天适用，没选就是每天。
- **有设定的人**：迟到 / 早退改按自己的时间判断，不看 Group A / B。
- **没设定的人**：完全照旧。

### 资料（V1 兼容）
- 员工资料新增选填字段 `fixedShift: { checkIn: 'HH:MM', checkOut: 'HH:MM', days?: number[] }`。
- 只新增，不改动既有字段。V1 不认识这个字段，会照旧按 Group 时间算。

### 程序
在 `getTargetShiftForDate` 前面加一层：员工有 `fixedShift`、而且当天适用，就回传它的时间。考勤审核、主控台、薪资迟到扣款都经过这一个地方，所以三处会一致。

## 3. 影响与回滚
- **只影响有设定的员工**，而且只影响设定之后才计算的考勤和薪资。已经结算的薪资不会重算。
- **回滚**：把员工的固定时间清空，就恢复按 Group 时间。

## 4. 测试
- 单元测试：有 / 没有固定时间、只有部分星期适用、跨午夜时间。
- Emulator：导入一天考勤，确认有固定时间的员工按自己的时间判断迟到。

2. 设定固定时间的员工，周末要不要也按同一组时间？
