# FACE3000-U 考勤审核导入与人工成本分析（Issue #8 · 第一阶段）

## 1. 流程

1. 进入「考勤管理」→「导入打卡」，选择 FACE3000-U 汇出的 `.XLS`（含 Summary、Logs）。
   - PDF 报表解析后，也转入同一个审核流程，不再直接写入。
2. 档案只在浏览器内解析，**按「确认导入」之前不写入任何资料**。
3. 以员工编号对应 ERP 员工：
   - 先比对人事档案的「考勤机编号」（新的选填栏位 `attendanceDeviceNo`）；
   - 没有设定时，比对员工 ID。
   - 对不上的编号逐一列出，主管必须手动对应或选择略过。
4. 系统按 ERP 的考勤设定重新计算，列出异常，主管可以逐项或批量处理（批量只套用到未处理的项目）。
5. 全部异常处理完、填好审核人，才能按「确认导入」。
6. 「人工成本与盈利」分页：显示雇主人工成本、人工成本率、保本营业额、预估利润。资料不完整时标为「估算」，并列出原因。

## 2. 解析规则

| 项目 | 规则 |
| --- | --- |
| 资料来源 | 只用 **Logs** 的原始打卡时间。机器的班表（11:00–14:30、16:00–00:30）与店里实际不同，机器算的迟到早退不采用 |
| 营业日 | 分界默认 06:00：此时间前的打卡算前一天的班（跨午夜下班）。可在画面调整 |
| 上个区间的打卡 | 例如 9 月 1 日凌晨的下班卡属于 8 月 31 日，只显示，不导入 |
| 重复打卡 | 同一营业日内相隔 5 分钟以内的只算一次 |
| 一天多次打卡 | 两两配对（上班、下班、上班、下班……），中间是休息，不计工时 |
| 班表 | 沿用「考勤设定」的平日、周末、特别时段、班次 2 与宽限分钟（`getTargetShiftForDate`） |

## 3. 异常与处理方式

| 异常 | 条件 | 主管可选 |
| --- | --- | --- |
| 漏打卡 | 当天打卡次数为单数（区间最后一天会提示下班卡可能在下个月的档案） | 补上时间 / 不算出勤 |
| 迟到 | 上班晚于班表超过宽限分钟 | 确认 / 豁免（须填原因） |
| 早退 | 下班早于班表超过宽限分钟 | 确认 / 豁免（须填原因） |
| 加班 | 下班比班表晚 30 分钟以上（可调整） | 批准 / 不批准；**只有批准的才计入** |
| 班次过长 | 上班到下班超过 14 小时 | 确认 / 不算出勤 |

## 4. 写入的资料（V1 兼容性说明）

- 考勤记录写入现有的 `attendance` 集合，沿用现有格式与 ID `attendance_<员工ID>_<营业日>_face`：
  - 与旧的打卡机导入相同，同员工同营业日会被取代，不会重复；
  - 不删除任何记录。
- 只新增选填栏位，V1 不读也不受影响：
  - `lateExcused`：已豁免迟到；
  - `approvedOtMinutes`：已批准的加班分钟数；
  - `importBatchId`、`reviewedBy`、`reviewedAt`：哪一次导入、谁审核、何时审核。
- `allTimes` 维持原本的 `HH:mm` 格式。跨午夜由 `clockIn` / `clockOut` 表示，不加「+1」。
- **重新导入**：同员工、同区间内，以前导入过（ID 以 `_face` 结尾）但这次没有的记录会被移除。
  - 包括这次判定不算出勤的日子，以及旧版按日历日导入、把凌晨下班卡存成另一天的错误记录。
  - APP 打卡与其他员工的记录一律不动。
  - 确认对话框会列出要移除的笔数；移除前会完整备份。
- 新集合 `attendance_import_batches`：每次导入一笔，**不存打卡明细**。
  - 记录区间、档名、员工数、略过的编号、各类决定的数量、审核人、写入与移除的记录 ID；
  - 子集合 `replaced` 存放被移除记录的完整备份，可据此还原。
- **写入顺序**：
  1. 先建立导入记录，状态 `PENDING`；
  2. 备份要移除的记录；
  3. 分批写入与移除；
  4. 状态改为 `COMPLETED`。
  - 中途失败可以再按一次「确认导入」：同样的记录会覆盖，不会重复。
  - 留下的 `PENDING` 记录可用来找出未完成的导入。
- `employees` 新增选填栏位 `attendanceDeviceNo`，用于机器编号与员工 ID 不同的人。

## 5. 与薪资的连动

- **法定扣款共用**：EPF、SOCSO、EIS、LINDUNG 与历史底薪的函数，从 `HRPayroll.tsx` 原封不动搬到 `utils/payroll/statutory.ts`。薪资与人工成本分析共用同一份，逻辑与费率不变，已有测试锁定数值。
- **豁免的迟到不扣款**：薪资计算迟到扣款时，跳过 `lateExcused: true` 的记录，也就是主管已豁免的迟到。
  - 只影响这次新流程写入的记录。
- **加班费尚未自动带入薪资（待负责人批准）**：
  - 已批准的加班存在 `approvedOtMinutes`；
  - 薪资画面的「加班」栏位仍由人手填写；
  - 自动带入属于资金逻辑变更，费率和时薪算法要先由负责人确认，见第 7 节。

## 6. 人工成本计算

```
雇主人工成本 = 应发薪资（底薪 + 已批准加班 + 启用中的固定津贴）+ 雇主 EPF + 雇主 SOCSO + 雇主 EIS
员工自付     = 员工 EPF + SOCSO + EIS + LINDUNG
人工成本率   = 雇主人工成本 ÷ 营业额
保本营业额   = （雇主人工成本 + 其他固定成本）÷（1 − 变动成本率）
预估利润     = 预估营业额 ×（1 − 变动成本率）−（雇主人工成本 + 其他固定成本）
```

**不重复计算**：

- 员工自付的部分已经包含在应发薪资里，只另外列出，不再加进成本。
- 当月已发放（POSTED）薪资的员工，以实际薪资为准；其余才用考勤推算。同一人只算一次。
  - 草稿仍可能修改，照样用推算。
- 「其他固定成本」请填租金、水电等，**不要含薪资**。

**区间**：只在「1 号到月底」的档案计算人工成本。薪资与营业额都以月计，跨月区间不计算；考勤审核与导入照常。

**营业额**：

- 取该月的每日结算（POS 加外送平台总额）。
- 天数不足整月时按日均推估整月，并标为估算。

**算法依据**：

- 月薪员工：加班时薪 = 月薪 ÷ 26 ÷ 8 × 1.5（雇佣法令算法）。
- 日薪员工：按出勤天数计。
- 时薪员工：按工时计。
- 当月入职或离职的员工会注明「以薪资模块按比例计算为准」。

## 7. 待负责人决定

1. **加班费**：
   - 是否在薪资计算时自动带入已批准的加班？
   - 倍数（平日 1.5、休息日 2、公共假期 3？）
   - 时薪算法用 ÷26÷8，还是沿用迟到扣款的 ÷30÷10？
2. **营业日分界**：要用 06:00 吗？这份 9 月档案在 02:00–09:59 之间没有任何打卡。
3. **考勤设定的班表**：机器上的班表是 11:00–14:30、16:00–00:30，实际上班约 14:30–15:30、下班约 00:30–01:50。请确认「考勤设定」与实际班表一致，否则会出现大量迟到或早退异常。
4. **变动成本率与其他固定成本**：目前由人手输入，是否改为自动取损益表的食材、包装与租金水电？

## 8. 权限（已知风险，随 CHG-05 / CHG-06 处理）

- 目前正式 Firestore Rules 允许任何已登录身份读写所有集合，这是紧急整改计划 CHG-06 的范围。
  - 因此「只有主管能导入」现在只是画面上的限制，不是真正的权限控制。
  - 这不是这次才有的问题：`attendance` 与薪资原本就能从浏览器直接写入。这次没有扩大可写入的范围。
- CHG-06 收紧 Rules 时，须将 `attendance` 与 `attendance_import_batches` 的写入限制为管理层以上，或改由服务端写入。
- 修改正式 Rules 需要负责人批准，本 PR 不修改。
