# FACE3000-U 考勤审核导入与人工成本分析（Issue #8 · 第一阶段）

## 1. 流程

1. 进入「考勤管理」→「导入打卡」，选择 FACE3000-U 汇出的 `.XLS`（含 Summary、Logs）。
   - PDF 报表解析后，也转入同一个审核流程，不再直接写入。
2. 档案只在浏览器内解析，**按「确认审核」之前不写入任何资料**。
3. 以员工编号对应 ERP 员工：
   - 先比对人事档案的「考勤机编号」（新的选填栏位 `attendanceDeviceNo`）；
   - 没有设定时，比对员工 ID。
   - 对不上的编号逐一列出，主管必须手动对应或选择略过。
4. 系统按 ERP 的考勤设定重新计算，列出异常，主管可以逐项或批量处理（批量只套用到未处理的项目）。
5. 全部异常处理完、填好审核人，才能按「确认审核」。
6. 「人工成本与盈利」分页：显示雇主人工成本、人工成本率、保本营业额、预估利润。资料不完整时标为「估算」，并列出原因。

## 2. 解析规则

| 项目 | 规则 |
| --- | --- |
| 资料来源 | 只用 **Logs** 的原始打卡时间。机器的班表（11:00–14:30、16:00–00:30）与店里实际不同，机器算的迟到早退不采用 |
| 营业日 | 分界默认 06:00：此时间前的打卡算前一天的班（跨午夜下班）。可在画面调整 |
| 上个区间的打卡 | 例如 9 月 1 日凌晨的下班卡属于 8 月 31 日，只显示，不导入 |
| 重复打卡 | 同一营业日内相隔 5 分钟以内的只算一次 |
| 一天多次打卡 | 两两配对（上班、下班、上班、下班……），中间是休息，不计工时 |
| 班表 | 沿用「考勤设定」的平日、周末、特别时段、班次 2 与宽限分钟（`getTargetShiftForDate`） |

## 3. 异常与处理方式

| 异常 | 条件 | 主管可选 |
| --- | --- | --- |
| 漏打卡 | 当天打卡次数为单数（区间最后一天会提示下班卡可能在下个月的档案） | 补上时间 / 不算出勤 |
| 迟到 | 上班晚于班表超过宽限分钟 | 确认 / 豁免（须填原因） |
| 早退 | 下班早于班表超过宽限分钟 | 确认 / 豁免（须填原因） |
| 加班 | 下班比班表晚 30 分钟以上（可调整） | 批准 / 不批准；**只有批准的才计入** |
| 班次过长 | 上班到下班超过 14 小时 | 确认 / 不算出勤 |

## 4. 储存的资料（V1 零影响）

> 2026-10-13 负责人要求「V1 不动」：审核结果**只存入 V2 专用集合**，不写入、不覆盖、不删除 V1 的 `attendance`。

- `attendance_reviews/{review_<员工ID>_<营业日>}`：审核后的班次，沿用考勤记录的资料格式。
  - 包括上下班时间、工时、`allTimes`（HH:mm）、`lateExcused`、`approvedOtMinutes` 与审核人；
  - 同一天重新审核，会以最新结果取代。
- `attendance_import_batches/{id}`：每次审核一笔，**不存打卡明细**。
  - 记录区间、档名、员工数、略过的编号、各类决定的数量、审核人、写入的记录 ID；
  - 状态先为 `PENDING`，完成后改为 `COMPLETED`；失败可直接重试，不会重复。
- `employees` 新增选填栏位 `attendanceDeviceNo`（考勤机编号），用于机器编号与员工 ID 不同的人。V1 不读这个栏位。
- **不会**：
  - 改动 V1 的 `attendance`；
  - 改动迟到扣款、薪资、加班费；
  - 删除任何记录。

## 5. 与薪资的关系

- **法定扣款共用**：EPF、SOCSO、EIS、LINDUNG 与历史底薪的函数，从 `HRPayroll.tsx` 原封不动搬到 `utils/payroll/statutory.ts`。逻辑与费率不变，已有测试锁定数值。
- **不自动扣薪**：薪资仍只读 V1 的 `attendance`，本功能不影响迟到扣款。
- **不自动计算或发放加班费**：
  - 已批准的加班只存在审核记录里；
  - 人工成本分析默认也不计入加班，只注明时数；
  - 待负责人确认实际班表与加班规则后，另开 PR 启用。
- **日后若要让薪资采用审核结果**（例如以审核记录取代旧考勤），属于资金逻辑变更，须另行设计、备份并取得负责人批准。

## 6. 人工成本计算

```
雇主人工成本 = 应发薪资（底薪 + 启用中的固定津贴）+ 雇主 EPF + 雇主 SOCSO + 雇主 EIS（加班待规则确认，暂不计入）
员工自付     = 员工 EPF + SOCSO + EIS + LINDUNG
人工成本率   = 雇主人工成本 ÷ 营业额
保本营业额   = （雇主人工成本 + 其他固定成本）÷（1 − 变动成本率）
预估利润     = 预估营业额 ×（1 − 变动成本率）−（雇主人工成本 + 其他固定成本）
```

**不重复计算**：

- 员工自付的部分已经包含在应发薪资里，只另外列出，不再加进成本。
- 当月已发放（POSTED）薪资的员工，以实际薪资为准；其余才用考勤推算。同一人只算一次。
  - 草稿仍可能修改，照样用推算。
- 「其他固定成本」请填租金、水电等，**不要含薪资**。

**区间**：只在「1 号到月底」的档案计算人工成本。薪资与营业额都以月计，跨月区间不计算；考勤审核与导入照常。

**营业额**：

- 取该月的每日结算（POS 加外送平台总额）。
- 天数不足整月时按日均推估整月，并标为估算。

**算法依据**：

- 月薪员工：加班时薪 = 月薪 ÷ 26 ÷ 8 × 1.5（雇佣法令算法）。
- 日薪员工：按出勤天数计。
- 时薪员工：按工时计。
- 当月入职或离职的员工会注明「以薪资模块按比例计算为准」。

## 7. 待负责人决定

1. **加班费**：
   - 是否在薪资计算时自动带入已批准的加班？
   - 倍数（平日 1.5、休息日 2、公共假期 3？）
   - 时薪算法用 ÷26÷8，还是沿用迟到扣款的 ÷30÷10？
2. **营业日分界**：要用 06:00 吗？这份 9 月档案在 02:00–09:59 之间没有任何打卡。
3. **考勤设定的班表**：机器上的班表是 11:00–14:30、16:00–00:30，实际上班约 14:30–15:30、下班约 00:30–01:50。请确认「考勤设定」与实际班表一致，否则会出现大量迟到或早退异常。
4. **变动成本率与其他固定成本**：目前由人手输入，是否改为自动取损益表的食材、包装与租金水电？

## 8. 权限（已知风险，随 CHG-05 / CHG-06 处理）
