## 与 V2 的差异
| 项目 | V2 | V1 |
|---|---|---|
| 开通条件 | `AUTH_SERVER_ENABLED=true` 且有预览站门禁或 Emulator | `AUTH_SERVER_ENABLED=true`。<br>V1 没有门禁也没有 Emulator 模式；登录接口本来就对外，有限次与锁定。 |
| 找不到负责人 | 显示错误画面 | V1 没有这个画面。服务端模式下一律显示「请负责人执行管理指令」，**不提供网页初始化** |
| 单元测试 | vitest | V1 没有测试工具。核心档案与 V2 完全相同，已在 V2 执行 22 项单元测试 |

## 开关关闭时（预设）
- `/api/auth/config` 回 `enabled:false`，所有登录接口回 503。
- 前端照旧：匿名身份、浏览器比对 PIN，行为完全不变。
- 不初始化 firebase-admin、不连 Firestore。
- 旧版伺服器没有 `/api/auth/config`（会回 SPA 页面）：前端视为未开通。

## 测试（本机实际执行）
**命令**
- `tsc --noEmit`：通过；
- `npm run build`：通过。

**V1 生产包 `node dist/server.cjs` 的接口测试**
- 测试方式：环境变数强制连本机 Firestore / Auth Emulator（`demo-klk-erp`），虚构资料。**没有开启 V1 前端**，因为 V1 前端只能连正式 Firebase。
- 结果：
  - roster 不含 PIN；
  - 预设 PIN 登录只回改 PIN 凭证，不签发身份；
  - 弱 PIN 回 400；改 PIN 成功；凭证不能重复使用；
  - 改完：只存 scrypt 哈希，并同步 V1 的 `employees.pin`；旧 0000 回 401，新 PIN 回 200；
  - 连续错 5 次 → 正确 PIN 也回 429；
  - 老板入口：错误 PIN 回 401，正确回 200；
  - V1 旧格式（PBKDF2）设备 PIN 经服务端登录成功，claims 正确；
  - 建立设备：只有考勤权限的领班 403，老板 200；
  - verify-pin 正常；
  - 不存在 bootstrap 接口（404）；
  - 开关关闭：config 回 `enabled:false`，login 回 503。
- **注意：** V1 员工资料没有 `orgLevel`，老板的 claims 是 `lvl: CREW`。这符合设计：claims 只看明确栏位。
  - 画面与老板入口仍依 V1 的推断，不受影响；
  - **CHG-06 前必须先补齐 `orgLevel`**（方案第 4.2 节，需负责人批准）。
